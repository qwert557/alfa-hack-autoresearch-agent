# Автономный ИИ-агент для автоматизации ML-пайплайнов (Alfa Hack)

Командный проект, разработанный в рамках хакатона Альфа-Банка. Система представляет собой автономный цикл **AutoResearch**, который по описанию задачи (`task.md`) и табличным данным самостоятельно проводит разведочный анализ, выдвигает ML-гипотезы, генерирует и исполняет код обучения моделей, анализирует ошибки и итеративно улучшает метрику до формирования итогового `submission.csv`.

---

## Мой вклад в проект
В рамках командной разработки я спроектировала и реализовала первые два ключевых этапа пайплайна — **подсистему автоматического первичного анализа данных (EDA)** и **автономного агента-исследователя (Hypothesis Researcher Agent)**:

1. **Автоматическое профилирование данных и сжатие контекста:**
   * Обнаружение датасетов, валидация контракта данных и эвристическое определение идентификаторов (`dataset_intake.py`).
   * Статистический анализ признаков, таргета, дубликатов, IQR-выбросов, маркеров пропусков и сдвига распределений `train/test` (`eda.py`, `data_profiler.py`).
   * Двухуровневая архитектура профилирования (`full_profile` + `compact_context`) с алгоритмом адаптивного усечения метаданных под строгий бюджет токенов (`profile_layers.py`).
2. **Агент-исследователь на базе LangGraph:**
   * Граф состояний `HypothesisResearcher` с циклами вызова инструментов и самокоррекцией невалидного JSON (`researcher_agent.py`).
   * Интеграция **LLM Tool Calling** (`researcher_tools.py`) для точечного дозапроса статистик признаков и поиска по словарю `data_dictionary.csv`.
   * Динамический промпт-инжиниринг для холодного старта (*Cold Start*) и итеративного планирования экспериментов на основе истории и рефлексии (`researcher_prompts.py`).

## Ключевые инженерные решения в моих модулях

* **Context Compression & Token Budgeting (`profile_layers.py`):**
  На широких датасетах полный профиль не помещается в контекстное окно LLM. Модуль формирует компактный JSON-срез (`compact_context`, по умолчанию 2000 токенов) и при превышении лимита пошагово сжимает второстепенные секции (от вторичных полей словаря к корреляциям), гарантируя сохранение критических сигналов о качестве данных.
* **Двухуровневый доступ к данным (Summary + On-Demand Tools):**
  Агент получает сжатую сводку проблем датасета (дисбаланс классов, сдвиги распределений между `train` и `test`, высококардинальные категории), а при формировании конкретной гипотезы самостоятельно вызывает Python-инструменты для глубокой проверки нужных признаков.
* **Устойчивый Structured Output (`researcher_agent.py`):**
  Гипотезы валидируются через **Pydantic** (`HypothesisSchema`: формулировка, доказательства из EDA, план вмешательств, оценка вычислительной стоимости и критерий фальсификации). При ошибках парсинга граф LangGraph автоматически переводит модель в цикл исправления схемы.

## Структура репозитория

### Мои модули (EDA и генерация гипотез)
* `dataset_intake.py` — поиск табличных датасетов, определение ID-колонок и сборка контракта задачи.
* `eda.py` — базовая сводка схемы признаков, качества данных и распределения целевой переменной.
* `data_profiler.py` — класс `DataProfiler`: корреляции, `train/test` shift, аномалии и поиск по словарю признаков.
* `profile_layers.py` — генерация `full_profile` и адаптивное сжатие `compact_context` под бюджет токенов.
* `researcher_tools.py` — обёртка методов `DataProfiler` в LangChain Tools для LLM-агента.
* `researcher_prompts.py` — шаблоны промптов для Cold Start, итеративного цикла и сжатия истории запусков.
* `researcher_agent.py` — граф LangGraph (`HypothesisResearcher`) + Pydantic-валидация гипотез.

### Остальные модули системы (командная разработка)
* `solution.py` — главный оркестратор полного цикла AutoResearch и точка входа.
* `task_parser.py` — LLM-парсинг условия задачи (`task.md`) и определение целевой метрики.
* `experiment_runner.py` — LLM-кодогенерация, безопасный запуск экспериментов в отдельном процессе и автоисправление ошибок кода.
* `reflection_analyzer.py` — анализ результатов кросс-валидации, поиск аномалий и генерация текстовой рефлексии.
* `experiment_history.py` / `experiment_tracker.py` — хранение истории экспериментов и обновление лучшего `submission.csv`.
* `llm_config.py` / `resource_monitor.py` — конфигурация LLM-провайдеров и фоновый контроль RAM/CPU/Disk.
* `test_researcher.py` / `diag_codegen.py` — скрипты локального тестирования и диагностики генерации.
